# 회귀탑 전투 아트 제작 기준

픽셀 슬라임 웅덩이와 검사를 같은 전장에 띄워 기준을 잡는다. 슬라임의 해골이 점액에 잠기는 공격 예고처럼, 장식 하나의 모양과 움직임만으로 다음 행동을 읽을 수 있어야 한다. 검사처럼 손, 손잡이, 가드, 칼날이 몸의 관절을 따라 이어져야 한다. 동작·기믹 설계와 실제 판정 대조는 [몬스터 기획 양식](monster-design-template.md)을 따르고, 이번 이식의 적용표는 [2026-11-29 전투 아트](enemy-motion-art/ARTWORK-2026-11-29.md)에 있다.

새 대상을 추가할 때는 도감 설명, 전투 의도, 실제 로딩 경로, 간접 호출되는 패리·소환·패배 화면부터 확인한다. 담당자들은 서로 다른 폴더에 작업한다. 두 작업자가 같은 시트나 전역 매니페스트(`art-source/enemy-motion/manifest.json`)를 덮어쓰지 않도록 최종 병합은 통합 담당이 맡는다.

## 몬스터 한 종의 작업 순서

1. 실제 크기로 슬라임 옆에 세우고 외곽선만 채운다. 비슷해 보이는 두 종을 붙여 머리, 지지하는 다리, 무기 윤곽 중 무엇으로 구분되는지 확인한다.
2. 대표 자세에서 발·몸통·앞팔·얼굴·무기의 가림 순서를 정한다. 접지 기준과 손이 닿는 지점을 기록한다. 반짝임은 젖은 점액, 긁힌 금속, 마른 돌의 차이를 보여주는 부위에 둔다.
3. 대기 두 키에서는 같은 발이나 지지면을 남기고 한 파트만 움직인다. 공격 준비에서는 무게를 모으고, 피격에서는 맞은 부위가 먼저 꺾인다. 같은 자세를 좌우로 미는 것만으로 두 상태를 대신하지 않는다.
4. 접근·접촉·후속·연타·특수 공격을 각각 무기나 신체의 실제 닿는 픽셀에 등록한다. 일반 피해·강한 피해·넘어짐·최종 잔해 키를 만든다. 덩치가 작으면 낮은 자세의 방어와도 맞추고, 접점 높이를 맞추는 동안 발이 바닥으로 들어가지 않는지 본다.
5. 파츠를 합성해 게임 PNG와 일치하는지, 인접한 셀을 침범하는지, 매니페스트의 범위·피벗·공격점이 원본에 맞는지 확인한다. 편집 파일과 투명 PNG를 같은 리비전으로 묶는다.
6. 그림이 넓어지거나 커지면 `src/arena.ts`의 배치 수치(`reach`·`restReach`·`head`)를 새 잉크가 이전 잉크보다 늘어난 만큼만 늘린다. 320px에서 예고·체력 카드·화면 끝과 겹치지 않는지 실제 전투로 확인한다.

## 배경 한 장의 작업 순서

1. 지역을 구분하는 큰 형상 하나를 잡는다. 회랑의 막힌 작은 아치, 석실의 사슬과 버팀목, 성소의 원형 비문, 돌계단의 붉은 녹, 성벽 통로의 총안, 관문의 잠금쇠와 끊긴 사슬을 작은 전장에서도 찾을 수 있어야 한다.
2. 전경·중경·후경을 나눠 그린다. 상단 왼쪽에서 오는 빛을 기준으로 마모와 재질을 남긴다. 검사 얼굴·검끝, 해골·촉수, 예고 UI 뒤를 먼저 비워 둔다.
3. 일반 전투 배경은 144×256이며 y=204가 벽과 바닥의 경계다. 좁은 화면은 144×144 보조 벽(`-compact`)을 하단 기준으로 잘라 같은 바닥 위에 놓는다. 원형 각인과 사슬 고리가 찌그러지지 않는지 실제 렌더에서 확인한다.
4. 상층 후열 석단(`upper-rear-ledge`, 84×24, 반투명 허용)은 지역 벽 다음, 모든 배우 앞에 그린다. 화면 폭의 53.5% 지점부터 오른쪽 끝까지, 앞줄 바닥 y에서 후열 높이만큼 위로 고정한다. 불투명 첫 줄(y=0)이 후열의 발판이다. 적이 전진해도 석단은 움직이지 않는다.

- `compile-enemy-motion-art.mjs`를 인자 없이 실행하면 상층 다섯 시트만 Aseprite에서 다시 내보낸다. 하층 몬스터는 `art-source/monsters`가 원본이므로 raw에서 다시 컴파일하지 않는다(시도하면 오류). 내보낸 RGBA가 기존 파일과 같으면 승인된 PNG 바이트를 그대로 둔다. 매니페스트의 칸·피벗·경계·접점은 유지하고 `alphaPixels`와 `drawing`만 칠한 칸에서 다시 계산한다.
- `upper-shield/down`의 기록된 경계 `[4, 30, 25, 13]`은 첫 상층 컴파일 때부터 실제 잉크 `[5, 30, 24, 13]`보다 1텍셀 넓다. 배치가 이 값에 맞춰져 있어 기록값을 유지하고, 컴파일러가 칠한 잉크를 별도로 대조한다.
- `python scripts/verify_art.py`(Pillow 필요, `npm run verify:art`)는 편집본 합성과 게임 PNG, 매니페스트 경계·접지·공격점, 검사 접점 픽셀, 슬라임 클립 범위, 배경 ORA, 상층 Aseprite를 함께 대조한다.
- 검사의 발 디딤 원작은 LuizMelo의 CC0 Hero Knight다. 원문은 [licenses/Hero-Knight.txt](../licenses/Hero-Knight.txt)에 있다.

## 최종 검수

실제 로비에서 대상을 선택하고 전투를 시작한다. 대기, 주사위 배치, 준비, 명중, 방어, 피격, 사망을 전투 결과와 대조한다. 작은 시종 동시 등장, 골렘의 패리, 보스 특수기, 상층 전열·후열 공격과 격파, 좁은 화면, 모션 감소 중 변경과 관련된 조건을 포함한다. 정지 시트만으로 확인한 부분은 그렇게 표시한다. 프레임이나 배경이 바뀌면 바뀐 장면을 다시 캡처한다.
