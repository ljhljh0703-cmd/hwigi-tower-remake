# 320px CI 스모크 수정

`codex/integrate-1127`의 `c41a2bf`를 기준으로 수정했다.

## 두 실패의 원인과 수정

| 실패 | Ubuntu CI에서 확인한 값 | 수정 |
| --- | --- | --- |
| 강적 유물 유지 | 안내 상단 `85.28125px`, 보스 유물 슬롯 하단 `88px`. 안내가 슬롯 하단보다 `2.72px` 위에서 시작했다. | 보상·보스 유물·상점 안내를 화면 제목 바로 위에 배치했다. 안내가 닫혀도 같은 화면에서는 공간을 유지해 선택 버튼이 움직이지 않는다. |
| 다섯 전투 예고 | 넘어뜨리기 도움말의 텍스트 영역 2개, 테스트 기대값 1개. | 줄 수 비교를 없애고 텍스트 영역을 모두 도움말 안에서 표시하는지 확인한다. 도움말이 화면에 모두 표시되는지와 주사위 배치·회수에 따른 예고 변경 검사는 유지했다. |

두 실행에서 같은 값이 기록됐다. [최신 실패 실행](https://github.com/ljhljh0703-cmd/hwigi-tower-remake/actions/runs/46090159631/job/140808961095) · [직전 실패 실행](https://github.com/ljhljh0703-cmd/hwigi-tower-remake/actions/runs/46089692926/job/140807441976)

## 재현과 검증

- 최신 CI 실행은 Ubuntu 26.04.1 이미지와 Headless Chromium `159.0.8154.6`을 사용했다. 로컬에서는 Windows에서 같은 버전의 Chromium을 실행하고, CI에 설치된 Ubuntu `fonts-wqy-zenhei` 패키지의 한글 글리프를 사용했다. 글꼴 크기 보정 115%와 장착 유물 줄 높이 증가를 적용해 화면이 밀리는 조건을 만들었다. Ubuntu 러너 전체는 로컬에서 재실행할 수 없었다.
- 320×568에서 수정 전에는 안내와 슬롯이 세로로 `3.23px` 겹쳤다. 같은 조건에서 수정 후 안내 상단과 슬롯 하단 사이에 `17.45px`의 간격이 생겼다. 320×568과 390×844 모두 안내 전체가 보였고, 안내를 닫기 전후 유물 유지 버튼의 위치가 같았다.
- 넘어뜨리기 도움말은 320×568에서 두 줄, 390×844에서 한 줄로 표시됐다. 두 크기에서 도움말과 글자가 모두 잘리지 않았고, 주사위를 놓으면 해당 예고가 활성화됐다.
- 빌드, 단위 테스트 180개, 모바일 스모크 84개가 통과했다. 강적 유물 세 장과 유지 보너스 동전 2개의 1회 지급, 새로고침 복원을 스모크에서 확인했다.
- `npm run bot`의 6개 정책 출력은 `c41a2bf`와 같았다.
